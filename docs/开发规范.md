# 嘟嘟开发规范

这些条来自已经发生过的故障和修法。改相关代码时先对照这里。手册在 [开发者手册.md](开发者手册.md)。

## 滑动

嘟嘟的无障碍服务一直开着。Compose 只要发现有启用的无障碍服务，就会在布局位置变化时于主线程重排无障碍树。普通 `verticalScroll` 和 `LazyColumn` 每次滑动都在改位置，所以会周期性掉帧。编辑页上量到过一帧里几十毫秒的组合，以及 40–120 毫秒的顿挫。

现在的做法：

- 任务列表、编辑、权限、检查屏幕只用 `LayerScrollColumn`。
- 滑动只改图层的 `translationY`，并用 `ViewParent.onDescendantInvalidated` 请求重画。不要 `View.invalidate()`，那会把整棵界面重新录进显示列表。
- 图层要包住内容的真实高度。`wrapContentHeight(unbounded = true)` 在外，平移在内，外面的盒子负责裁剪。图层若只有一屏高，画面能滑，点下去仍落在没滑之前的位置。
- 输入框不要跟滑动抢位置。`NoChaseBringIntoView.calculateScrollDistance` 保持返回 0。
- 步骤卡片平时不要挂 `graphicsLayer`。只在长按拖动、或邻卡让缝时再挂。
- `graphicsLayer { translationY = state }` 这种块写法会在摆放时读状态，整页重新测量。滑动不要用它。
- 选应用可以继续用 `LazyColumn`。全部应用加图标收不进一层。不要为了「统一」把它改成 `LayerScrollColumn`。

以后新页面要滚动，先用 `LayerScrollColumn`。只有内容长到放不进一层时才用 `LazyColumn`，并在旁边写明原因。

不要为了滑动顺手删掉长按拖动、编辑、置顶、上移、下移、删除或点选。这些都曾被误当成卡顿原因拿掉过。

## 无障碍服务开多大

空闲时只要 `TYPE_WINDOW_STATE_CHANGED` 和 `FLAG_REPORT_VIEW_IDS`。配置文件 `accessibility_service_config.xml` 也是这一档。

读窗口、拿 view id、看遮罩底下的界面，需要 `FLAG_RETRIEVE_INTERACTIVE_WINDOWS` 和 `FLAG_INCLUDE_NOT_IMPORTANT_VIEWS`，再加上 `TYPE_WINDOW_CONTENT_CHANGED`。这些只在两处打开：

- `KeepAliveService` 执行步骤的那一段，`finally` 里关掉。
- 点选遮罩显示期间。取消、失败、隐藏都要关掉。

点选时要先拿掉遮罩，再 `hitTest`。遮罩还盖着时，它是活动窗口，底下的控件 id 是空的，结果就只剩一个坐标。

空闲时把检索一直开着，编辑页滑一会就会再变卡。执行中途忘记关掉，也一样。

`ignoredPackages()` 只服务 `onAccessibilityEvent`，用来决定哪个窗口可以记成「用户刚才看的应用」。成员只有：桌面、已启用输入法、嘟嘟自己、`com.android.systemui`、`android`。

手机管家（`com.miui.securitycenter`）、设置、权限控制器、`com.miui.securitycore`、`com.lbe.security.miui`、`com.miui.powerkeeper` 放在 `BlockedPickPackages`，只给 `isPickTarget()` 用。把它们写进 `ignoredPackages()` 会让每次事件都变重，编辑页滑动会再次变卡。点选跳进手机管家，是 `lastExternalPackage` 被系统窗口盖掉了，要在点选那一刻拦截，不要在事件路径上拦截。

父节点搜索要进 `Session` 再回收。只回收根节点，长时间运行后节点会积下来。

## 点击控件

新点选保存 `CLICK_TARGET`：view id、文字、描述、坐标都留下。执行时先找控件，找不到再点坐标。只有 id、文字、描述全空时才直接点坐标。

不要再拆成「点选」和「手填 id」两个入口，也不要改成只记坐标。只记坐标过不了会校验点击来源的页面；只记 id 又点不了 WebView 里的按钮。

点选遮罩是全屏透明的，没有顶部取消条。取消条会挡住用户要点的控件。点完才出底部结果卡。

`CLICK_ID` 是旧数据，执行和编辑都要还能用。

## 界面栈

`MainActivity` 保持 `singleTask`。从闹钟、通知进主界面必须带 `NEW_TASK | CLEAR_TOP | SINGLE_TOP`。曾经因为每次闹钟都新开一个主界面，栈上叠了 5 个，编辑页要杀进程才恢复顺滑。

`WakeActivity` 保持 `singleInstance` 和空的 `taskAffinity`，用完就关掉。不要把它放进主任务栈。

## 闹钟和间隔

间隔的下一次存在 `nextRunAt`。`scheduleNext` 的 `resetInterval` 默认 false。只有保存、重新启用、导入启用任务时传 true。

到点后续订、开机恢复、进程被拉起后的 `rescheduleAll`，都沿用已有的 `nextRunAt`。否则「每 5 分钟」会在每次广播里被改成「从现在再加 5 分钟」。

`AlarmReceiver` 和 `BootReceiver` 的协程做完就结束作用域。不要挂一个不会取消的全局 scope。

一次任务在有别的任务正在跑时，推迟大约 1 分钟，不要直接丢掉，也不要把它当成间隔任务去改 `nextRunAt` 的算法。

## 进程、库文件、这台 MIUI

不要随便 `am force-stop com.lytalk.dodo`。这台 MIUI 上这样停进程会把 `enabled_accessibility_services` 清成空，`accessibility_enabled` 变成 0。任务看起来还在，到点却点不了。若确实停过，要用 root 把服务组件写回去，并打开 `accessibility_enabled`。

换 `dodo.db` 时保住原 inode 和 SELinux 标签：写入现有文件、删除 wal 和 shm、改回应用 uid、`restorecon`。设备上没有 `sqlite3`，在电脑上打开拉下来的 db 和 wal。

不要停用或改写用户机器上的 `com.rea.autotask`。

这台手机上已有的打卡任务不要改、不要跑。验证用测试任务。编辑页返回即放弃，除非这次就是在测保存。

`adb shell uiautomator dump` 开头的 `theme_compatibility.xml` 错误可以忽略。图层平移之后，dump 里的 bounds 不是屏幕上的位置。

## 备份和导入

小米云服务不备份第三方应用的内部数据。不要把它写成「已经支持小米云备份」。现在的实现是系统备份规则：只包含 `dodo.db` 及其 wal、shm，并在全量备份前做 WAL checkpoint。Android 12 上，规则里写了 include，就只会备份这些文件。

导入是追加。不要顺手删掉手机上的任务。不要把 `lastRunAt`、`lastResult`、`nextRunAt` 抄进来。启用的任务导入后要重新登记间隔。

JSON 版本是 1。不认识的步骤类型丢掉。没有步骤的任务丢掉。大于 2_000_000 字节的文件拒绝。

## 改完怎么确认

改滑动：在真机上滑那一页，看 `dumpsys gfxinfo` 的帧时间，并确认内容确实动了。再点一个滑到新位置上的按钮，确认打开的是画面上的那一项。只看截图不算验证。

改点选：在原生按钮上点一次，结果卡里应出现 `包名:id/...`。WebView 按钮可以没有 id，但应有坐标。不要点到删除任务。

改调度：看下一次时间是否仍是保存时登记的那次，而不是被拨到「从现在开始」。

改无障碍开关：做完动作后确认服务回到空闲标志（只有窗口状态变化和 report view ids）。用编辑页滑一下，不该重新变卡。
