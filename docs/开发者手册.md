# 嘟嘟开发者手册

这份手册描述当前工作区里的实现，给以后改嘟嘟的人看。用户怎么用，以 [README.zh-CN.md](../README.zh-CN.md) 为准；两边不一致时，以代码和本手册为准。

当前版本是 `1.0.3`（`versionCode` 3，标签 `v1.0.3`）。这一版把页面滑动改成整层平移，点选时才打开窗口检索，点击控件先找控件再按位置兜底。

产品一句话：到点打开用户选的应用，按步骤操作。口号是「让手机按时帮你做事」。包名 `com.lytalk.dodo`。

## 运行环境和工程

实测机是 Redmi K40（`M2012K11AC` / `alioth`），MIUI 13.0.7，Android 12，API 31，arm64-v8a，已 root。屏幕 1080×2400，密度 440，可用高度大约 2276。自启动、后台弹出界面、省电入口按这台 MIUI 写。

## 代码地图

```
app/src/main/java/com/lytalk/dodo/
  MainActivity.kt          单实例导航
  DodoApp.kt               通知渠道
  ui/                      Compose 页面
  data/                    Room、时间计算、导入导出、备份
  a11y/                    无障碍、点选、步骤执行
  schedule/                闹钟、前台服务、开机、root、企业微信
  miui/                    这台 MIUI 的设置入口
```

导航在 `MainActivity`，`NavHost` 起点是 `list`：

| 路由 | 页面 |
| --- | --- |
| `list` | 任务列表 |
| `edit?taskId={taskId}` | 编辑。`taskId` 为 0 是新建 |
| `picker` | 选择应用 |
| `permissions` | 权限 |
| `inspect` | 看当前屏幕上的控件 |

`MainActivity` 是 `singleTask`。闹钟和通知打开它时带 `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TOP | FLAG_ACTIVITY_SINGLE_TOP`，避免任务栈上叠出多个主界面。`WakeActivity` 是 `singleInstance`、空 `taskAffinity`，只负责亮屏，不进最近任务。

## 数据

数据库文件是 `dodo.db`，Room 版本 6。有 1→6 的迁移，没有破坏性重建。加字段要再写迁移，并升高 `@Database(version)`。

`tasks` 的主要列：

| 列 | 含义 |
| --- | --- |
| `scheduleType` | `ONCE` `DAILY` `WEEKLY` `INTERVAL_MINUTE` `INTERVAL_HOUR` |
| `hour` / `minute` | 每天、每周是钟点。每小时用 `hour`（1–24）。每分钟用 `minute`（1–59） |
| `daysMask` | 每周的星期位 |
| `onceAtMillis` | 只执行一次的时间 |
| `nextRunAt` | 间隔任务的下一次。v6 加上的 |
| `retryCount` | 失败后从头再跑的次数，界面上是 0–3 |
| `cleanupType` | `NONE` `HOME` `CLOSE_LAUNCHED` `STEP` |
| `lastRunAt` / `lastResult` | 上次执行。导入时丢掉 |

`steps` 按 `taskId` 外键级联删除，`position` 从 0 起。步骤类型和 payload 都是字符串，payload 是 JSON，见 `StepTypes` 和 `StepPayloads`。

列表顺序是 `enabled DESC, id DESC`。

## 时间

计算在 `ScheduleCalculator`，登记在 `AlarmScheduler`。

- 每天：今天这个钟点还没到就今天，否则明天。
- 每周：从今天起最多看 8 天，掩码里有这一天且钟点还没过。
- 一次：`onceAtMillis` 仍在未来才登记。闹钟触发并跑完后关掉任务。若当时已有任务在跑，把这一次推迟 1 分钟。
- 每分钟 / 每小时：间隔存在 `nextRunAt`。没有记录，或调用时 `resetInterval = true`，就从现在再加一个间隔。否则沿旧的 `nextRunAt` 按间隔补到未来。

`resetInterval = true` 只出现在三处：保存、重新启用、导入一个启用的任务。到点后续订、开机恢复，都不要重置，否则间隔会被拨到「从现在再算」。

登记用 `AlarmManager.setAlarmClock`。每个任务一个 `PendingIntent`，request code 是任务 id。没有精确闹钟权限就只打日志，不登记。状态栏闹钟图标来自 `setAlarmClock`，不是用户自己在时钟里设的。

有启用任务时，`KeepAliveService` 以前台服务留在通知栏（「嘟嘟守护中」）。到点由 `AlarmReceiver` 拉起它。开机和覆盖安装由 `BootReceiver` 把启用的任务重新登记。两个接收器都 `goAsync()`，协程结束就 `cancel` 作用域并 `pending.finish()`。

同一时刻只跑一个任务。第二个到来时，一次任务推迟，其他任务记下「已有任务正在执行」。

跑完若填了企业微信地址（`http://` 或 `https://`），`WebhookClient` 发一条文本。发送失败的说明附在 `lastResult` 后面。

## 步骤怎么执行

`KeepAliveService.runTask` 在执行前后成对调用 `setRetrievalActive`。失败也要关掉，写在 `finally` 里。

`StepExecutor` 按 `position` 跑。某一步返回非空字符串就是失败原因。然后先做兜底清理，还有次数就从头再跑。次数用完后保留原来的失败原因。清理自己失败时，说明补在结果后面。

| 类型 | 行为 |
| --- | --- |
| `LAUNCH_APP` | 启动所选应用 |
| `UNLOCK` | 只在锁屏时重放录下的滑动。已经解锁就跳过 |
| `CLOSE_APP` | 若该应用在前台，先回桌面，再用 root `am force-stop`。不能关自己 |
| `CLICK_TEXT` | 全界面找文字，找不到就滚动再找，大约 18 秒 |
| `CLICK_ID` | 按完整 view id 找，同样会滚动 |
| `CLICK_TARGET` | 见下一节 |
| `INPUT_TEXT` | 写入目标输入框。目标和 id 都空时，写焦点或第一个输入框 |
| `WAIT` | 毫秒，界面上最长 120 秒 |
| `WAIT_FOR_TEXT` | 等到文字出现 |
| `BACK` | 系统返回。这一步不能编辑 |

`CLICK_TARGET` 的顺序：

1. `viewId`、`text`、`description` 都空，但有坐标：只点坐标。这是旧的「只记位置」数据。
2. 否则先按 id，再按文字，再按描述，并滚动查找。
3. 还找不到，有坐标就点坐标。
4. 没有坐标就失败。

坐标是相对整屏宽高的比例，存在 `xFraction` / `yFraction`。WebView 里的按钮经常没有 id，父节点也不可点，所以必须留位置兜底。WPS 任务中心里的签到按钮就是这样。

点击文字时优先完全匹配，再点可点击的祖先。向上找的父节点要放进 `Session`，用完回收。漏回收会在长时间运行后把无障碍节点堆住。

## 点选控件

添加步骤里的「点击控件」只有一条路：去应用里点一下。点完看控件 id 和文字，确认后存 `CLICK_TARGET`（id、文字、描述、坐标都存）。没有单独的「手填 id」入口。旧的 `CLICK_ID` 步骤仍能执行，编辑时走同一个对话框。

点选过程：

1. `beginNodePick` 用 `lastExternalPackage` 决定回到哪个应用。这个包必须通过 `isPickTarget`。
2. 先 `setRetrievalActive(true)`，再打开目标应用，约 500 毫秒后盖上一层全透明遮罩。遮罩上没有取消条。
3. 用户点一下。先 `removeViewImmediate` 拿掉遮罩，再 `hitTest`。遮罩还在时，它是活动窗口，底下的应用读不到。
4. 底部卡片给出 id 或「控件 id：没有」，以及位置。确认文案是「用这个控件」。
5. 取消或离开时 `setRetrievalActive(false)`。

`hitTest` 跳过 `com.lytalk.dodo`，取包含该点的最小节点。

空闲时无障碍只收 `TYPE_WINDOW_STATE_CHANGED`，标志只有 `FLAG_REPORT_VIEW_IDS`。执行任务和点选时再临时加上 `TYPE_WINDOW_CONTENT_CHANGED`、`FLAG_RETRIEVE_INTERACTIVE_WINDOWS`、`FLAG_INCLUDE_NOT_IMPORTANT_VIEWS`。没有后两个标志，`getWindows()` 看不见遮罩底下的窗口，`viewIdResourceName` 也是空的，于是每次点选都只剩坐标。

`ignoredPackages()` 只用于每个无障碍事件：桌面、输入法、嘟嘟自己、`com.android.systemui`、`android`。手机管家、设置、权限控制器在 `BlockedPickPackages` 里，只在 `isPickTarget()` 判断。不要把它们放进事件忽略列表。

`lastExternalPackage` 会被最近一个非忽略窗口盖掉。所以点选前若系统窗口冒出来，可能回到错误的应用。拦截名单就是为了挡住手机管家和设置，而不是在每个事件里丢掉更多包。

## 界面

页面是 Jetpack Compose Material 3。

会滚动的页面用 `ui/LayerScroll.kt` 的 `LayerScrollColumn`：

- 任务列表
- 任务编辑
- 权限
- 检查当前屏幕

选应用仍用 `LazyColumn`。那一页是全部已安装应用，每行有图标，不能收成一张覆盖全列表的图层。

`LayerScrollColumn` 的做法：内容按真实高度量一次，画进一个 `GraphicsLayer`，手指移动时只改 `translationY`，再用 `ViewParent.onDescendantInvalidated` 请求重画。布局位置不变，所以无障碍树不会跟着每次滑动重排。图层包住整段内容，外面的盒子裁剪并接收滑动；这样点下去的还是画面上的那一项。输入框抢滚动被 `NoChaseBringIntoView` 挡住，它的滚动距离恒为 0。

编辑页的长按拖动还在。步骤卡片平时没有自己的 `graphicsLayer`。只有正在拖、或旁边的卡片在让缝时才加。置顶、上移、下移、删除、编辑都保留。

编辑中的步骤记在 `TaskEditViewModel.editingStepIndex`。保存进同一步时替换，否则追加。选应用或点选被取消时清掉这个下标，避免下一次添加写到旧位置。返回不保存。

## 导入、导出、备份

列表页可以导出、导入 JSON，版本号是 1，最大 2_000_000 字节。导入是追加，不删已有任务。不复制 `lastRunAt`、`lastResult`、`nextRunAt`。启用的导入任务会 `scheduleNext(..., resetInterval = true)`。类型不在白名单里的步骤丢掉。空步骤的任务丢掉。

系统备份只包含 `dodo.db`、`dodo.db-wal`、`dodo.db-shm`。`fullBackupOnly` 为 true。Android 12 上写了 include 就表示只备份这些文件。`DodoBackupAgent.onFullBackup` 先 `PRAGMA wal_checkpoint(FULL)`，再交给系统，避免任务还写在 wal 里。

这不是小米云服务的应用数据云备份。小米云服务不备份第三方应用的内部数据。这里做的是系统「备份与恢复」和换机时能带上 `dodo.db`。

## 在这台手机上改完要看什么

改的是界面、滑动、步骤编辑或点选时，装到这台手机上自己走一遍。只打开「测试僵尸」或用户指定允许动的任务。打卡任务不要改、不要跑。返回不保存，除非这次就是在验证保存。

```bash
adb shell input keyevent KEYCODE_WAKEUP
adb shell input swipe 540 1900 540 500 200
```

锁屏后先上滑。`uiautomator dump` 前面总会打一行 `theme_compatibility.xml` 找不到，后面的 XML 仍可用。无障碍节点的坐标是布局坐标；用了图层平移之后，它和屏幕上看到的位置不一致，要点按截图上的位置，不要按 dump 里的 bounds。

这台系统没有 `sqlite3`。要看库就把 `dodo.db` 和 wal 拉到电脑上。`adb shell` 里套 `su` 时，整段参数用单引号包住。

不要对嘟嘟 `force-stop`，除非正在换库文件。这台 MIUI 上 force-stop 会清掉 `enabled_accessibility_services`。换库必须保住原来的 inode 和 SELinux 上下文：停进程、把新文件写进原 inode、删掉 wal/shm、改回应用 uid、`restorecon`，然后再把无障碍服务写回去。不要停掉用户机器上的 `com.rea.autotask`。
